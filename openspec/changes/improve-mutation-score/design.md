## Context

See `proposal.md` for motivation. Current state relevant to this design:

- Mutation score after Round 3 is **73%** (1791 killed + 10 timeout / 2445 mutants; 644 survivors; `mutationScore` 73). Reaching 85% requires **~288** more kills (2445 × 0.85 = 2078.25 → 2079 killed; today 1791). Only `Killed` counts: `check-mutation-score.py` reads Mull's `mutationScore`, which ignores `Timeout`.
- Survivors (644) split by mutator class: **185** relational (`lt`/`le`/`gt`/`ge`), **174** equality (`eq_to_ne`/`ne_to_eq`), **117** arithmetic (`add`/`sub`/`mul`/`div`/`rem`), **103** inc/dec (`post`/`pre`), and 65 others.
- Survivors are concentrated by group: `compiler.cpp` relocation/layout 46, builder readers 135 (`resource_akm_reader` 78, `resource_spr_reader` 19, `resource_akx_reader` 12), compiler semantic 98, compiler statements 201, parser 99, symbols 20, lexer 17, cli/domain/infra 7.
- Round 2 implemented exhaustive enumeration (phases 7–9) but reported **70%** because tests asserted high-level properties. Round 3 rewrote them to assert exact emitted bytes (phases 11–15) and moved to **73%**. A residual class of survivors remains: **index/offset mutants** (`dest[address - N]` → `address + N`, `data[i + 1]` → `i - 1`) whose fixtures use **zeros or equal values**, so reading/writing the wrong offset yields a byte identical to the expected one and the mutant is equivalent *for that fixture* (e.g. `dest[address - 3]` mutated to `dest[address + 3]` reads an all-zero cell while the intended cell is also `0x00`). Round 4 addresses this with **distinct sentinel bytes per offset** (Decision 13).
- Tests are doctest 2.4.11 in `tests/unit/src/*.cpp`, one `test_unit` binary. `make mutation-run` uses `mull-runner-18 --timeout 32000 --minimum-timeout 32000 --allow-surviving --test-suite-exclude=Slow`.
- mull-runner 0.34.0 exposes **no per-mutant filter** (only `--dry-run` to enumerate without executing), so incremental verification is `make -C tests/unit run`; the full `make mutation-run` is a user-managed step. New tests compile without `-fpass-plugin`, so they do not change the mutant count.

## Goals / Non-Goals

**Goals:**
- Kill ~300 of the 644 survivors (2079 − 1791 = 288 required; ~12 margin) with test-only changes, ordered highest-kill-first, driven by the exact survivor locations in the latest `mutation_report.json`.
- Assert the **exact emitted bytes/values** each mutant alters, using **distinct sentinel bytes per offset** so that index/arithmetic mutants cannot be equivalent for the fixture (Decision 13).
- Keep every new test **kernel-reassembly-safe**: kernel-derived values are computed at runtime; only Z80 ISA opcodes, compiler-owned geometry, and the documented compiler↔kernel ABI are asserted literally (Decision 14).
- Reach 85% via kills; use `excludePaths` narrowing only as a fallback for provably equivalent mutants (in practice inapplicable at sub-file granularity — see Decision 8).

**Non-Goals:**
- Do NOT change production source code (`.cpp`/`.h` under `src/`), **except** the single minimal `Compiler::getContext()` accessor added in Round 3 (Decision 12). Round 4 is test-only.
- Do NOT convert the 10 timeout mutants to killed; they stay "Timeout".
- Do NOT run the full mull suite or `mutation-clean` during development (both are slow); verification is `make -C tests/unit run`, and the full `make mutation-run`/`make mutation-check` is the user's final step.
- Do NOT add `--dry-run`-based mutant enumeration as a workflow; it is unnecessary since the report already gives exact locations.

**In scope (fallback only):** `mull.yml` (`excludePaths`) — build/mutation config, not production code.

## Decisions

### Decision 1: Mutant-report-driven targeting

Each phase is scoped to the exact surviving mutant locations (file + mutator + line) from `mutation_report.json`. A phase's target list is generated by filtering the report, so every new test maps to concrete survivors.

- Rationale: Round 1's generic "add more subtype tests" did not move the needle; the survivors live in specific branches (opcode equality, immediate values, boundary comparisons) that generic tests never hit.
- Alternative: repeat the prior tier recipe — rejected; it already under-delivered.

### Decision 2: Exhaustive enumeration over representative sampling

Round 1 sampled one representative case per branch and left the rest unreached. Round 2 enumerates **every reachable case** for each targeted branch:

- the relocation switch in `compiler.cpp` → every reachable conditional `call`/`jp` opcode and the `0xFF` LOAD case (not just `jp z`/`jp nz`/`jp`);
- the AKM/AKX/MTF/SPR readers → every size boundary (`==`, `±1`) and every malformed/truncated error path, not just one boundary fixture;
- `compiler_expression_evaluator` and the graphics strategies → every `==`/`!=` type/subtype pair, not a couple of representative pairs;
- `compiler_code_optimizer` → every peephole pattern and every immediate-value branch, not the subset added in Round 1.

- Rationale: this is the core lesson of Round 1 — partial branch coverage leaves the majority of a module's mutants alive.
- Trade-off: more test code and fixtures, but each is data-driven and cheap once the enumeration is written.

**Outcome:** Round 2 implemented this enumeration but the user-managed run still reported 70% (only ~16 kills), because enumerating branches without asserting the exact emitted output leaves output-changing mutants alive — superseded by Decision 10.

### Decision 3: Phase ordering and kill budget

```
Phase 1 — easy   counters & boundary arithmetic   ~110-170 kills   (inc/dec + relational on tested paths)
Phase 2 — medium binary readers & strategies       ~130-190 kills   (boundary/malformed fixtures + both-sides)
Phase 3 — hard   type dispatch & relocation        ~75-120  kills   (eq_to_ne dispatch + relocation arithmetic)
Phase 4 — fallback scope narrowing                 0 kills          (only if equivalent mutants block 85%)
```

Ordering rationale: inc/dec and boundary mutants on already-tested paths need only an added assertion (lowest effort per kill); the binary readers need fixtures but are data-driven (medium); the `eq_to_ne` type dispatch and relocation arithmetic are the most expensive and carry the most equivalent-mutant risk (highest effort, done last). Phase 4 is a safety valve, not a planned phase.

**Outcome:** this was the Round 2 ordering. Round 3 re-orders highest-kill-first and re-budgets per `tasks.md` (11–16), superseded by Decision 10.

### Decision 4: White-box relocation tests cover every reachable opcode

The relocation switch (`Compiler::write`, `compiler.cpp` lines ~508-675) is exercised directly, not via BASIC that must coincidentally emit a given byte sequence. The existing MegaROM fixup test (Round 1 task 5.1) is extended to seed the fix list with a crafted fix for **every reachable opcode case** — conditional `call` (`nc`/`nz`/`c`/`z`), conditional `jp` (`nc`/`nz`/`c`/`z`), unconditional `call`/`jp`, and the `0xFF` LOAD case — and assert the exact emitted bytes, killing the `add`/`sub`/`mul`/`div`/`rem` and boundary mutants in each case body.

- The `jp m`/`pe`/`p`/`po` and `call p`/`po`/`m`/`pe` variants are **never emitted** by the compiler (no flag-tracking at that granularity); they remain unreachable and are candidates for Phase-4 scope narrowing, not white-box tests.
- Rationale: generating BASIC that emits each conditional across a 16 KB segment boundary is impractical; `Compiler::write` already exposes the fixup logic.
- Alternative: byte-exact fixtures through full compilation — rejected as too brittle and slow.

### Decision 5: Readers get exhaustive boundary + malformed fixtures

For `resource_akm_reader.cpp` (75 survivors), `resource_akx_reader.cpp`, `resource_mtf_map_reader.cpp`, `resource_spr_reader.cpp`, and `resource_csv_reader.cpp`, add fixtures at every size boundary (`==`, `±1`) and truncated/malformed inputs that drive each error path and both sides of every size comparison. These are data-driven and cheap once the boundary matrix is written.

### Decision 6: Type-dispatch equality is driven per pair

The `eq_to_ne` survivors in `compiler_expression_evaluator.cpp` (30), `compiler_copy/line/put/circle/get_statement_strategy.cpp`, `compiler_symbol_resolver.cpp`, and `compiler_variable_emitter.cpp` are killed by driving every type/subtype pair through the dispatch and asserting the emitted result. Where a subtype is unreachable by construction, it is recorded and left for Phase-4 consideration rather than faked.

### Decision 7: Verification is unit-suite only; single-mutant runs are unavailable

mull-runner 0.34.0 has no `--mutant`/`--include` filter, so a single-mutant run is not possible. Every task therefore verifies with `make -C tests/unit run` (fast, incremental; new tests compile without the mull frontend). No `mutation-build`, no `mutation-run`, and no `mutation-clean` are performed by the implementer. The user runs `make mutation-run` + `make mutation-check` once at the end to confirm ≥ 85%.

### Decision 8: Narrow the mutation scope only as a fallback

If Phase 3 leaves provably equivalent or unreachable mutants that block 85%, extend `mull.yml` `excludePaths` to exclude the specific defensive/unreachable regions (for example, the never-emitted relocation opcode cases, or defensive guards whose both branches are observably identical). This reduces the denominator rather than killing, so it is applied only after the test-led phases, and only for code whose equivalence is demonstrated in the design/tasks notes.

- Rationale: `excludePaths` is legitimate for third-party/unreachable code (already used for `pletter.cpp`), but over-applying it defeats the point of a mutation bar. It stays a last resort.
- Alternative: keep everything mutated and fail the 85% bar on equivalent mutants — rejected; equivalent mutants are, by definition, not killable.

**Outcome after implementation (task 10.1):** no additional `excludePaths` entries were added. Investigation showed `excludePaths` matches **whole file paths** (regex), so it cannot target individual switch cases, functions, or the never-emitted opcode branches. The unreachable/equivalent mutants identified during Phases 1–3 are scattered across files that also contain reachable code:

- `compiler.cpp` — never-emitted `jp m/pe/p/po`/`call p/po/m/pe` relocation cases, plus the reachable build/segment logic;
- `compiler_code_optimizer.cpp` — the `*pipeline[0] == 11` (should be `0x11`) dead peephole branch;
- `resource_akm_reader.cpp` — the linker state machine (out of scope by decision).

Excluding any of these whole files would also drop a large number of reachable, killable mutants and distort the score. The user therefore accepted these unreachable mutants in the final count, and `mull.yml` remains unchanged (only `pletter.cpp` excluded, as in Round 1).

**Recorded equivalent/unreachable mutants (accepted, not excluded):**

- `compiler.cpp` relocation: `jp m/pe/p/po` (0xFA/0xEA/0xF2/0xE2) and `call p/po/m/pe` (0xF4/0xE4/0xFC/0xEC) are never emitted by the compiler, but **Round 4 exercises them white-box** (Decision 14) because `Compiler::write` reads `dest[address-1]` from a caller-provided buffer and therefore must handle any opcode; they are no longer accepted as survivors. The conditional `call nc/nz/c/z` (0xD4/0xC4/0xDC/0xCC) and `jp nc/c` (0xD2/0xDA) were already exercised via `getContext()` (Decision 12).
- `compiler_code_optimizer.cpp:123`: `*cpuctx.code_pipeline[0] == 11` (should be `0x11`) is a dead peephole branch — accepted (Round 4 cannot distinguish it).
- `resource_akm_reader.cpp`: the linker state machine (~43 mutants) is out of scope by user decision.
- `cliparser.cpp` L37/L60, `fswrapper.cpp` L108, `resource_blob_reader.cpp` L36: reported as `Timeout`/equivalent — accepted.

### Decision 9: Carry forward Round 1's runtime/scope decisions

Decisions already made and implemented in Round 1 remain in force and are not re-decided here:

- Slow-test exclusion: the 8 KB blob test is tagged `TEST_SUITE("Slow")` and skipped during mutation via `--test-suite-exclude=Slow`, but still runs in `make run`.
- Timeout: `--timeout 32000 --minimum-timeout 32000` (the measured baseline ~27 s mull / ~45 s gcc exceeds the old 10-15 s assumption; no further change needed).
- doctest/test code is already out of mutation scope (test objects compile without `-fpass-plugin`).
- `--ld-search-path /lib/x86_64-linux-gnu:/lib64` silences the JIT library warnings.
- `pletter.cpp` is already excluded via `excludePaths`.

### Decision 10: Round 3 asserts exact emitted output (the Round 2 lesson)

Round 2's tests exercised the target branches but asserted only high-level properties, so arithmetic/relational/equality mutants that change *where* a byte is written or *which* branch is taken still survived. Round 3 changes the assertion contract from branch coverage to exact-output assertions:

- **Relocation (`compiler.cpp`)** is tested white-box: seed the fix list via `Compiler::write` with a crafted fix per reachable opcode (conditional call/jp `nc`/`nz`/`c`/`z`, unconditional call/jp, `0xFF` LOAD) and assert the exact `out[]` bytes at each patch position — `0x18 0x07` (same-segment `jr $+8`), `F5 08 D9 F1` (push/ex af,af'/exx/pop), `0x38/0x30/0x28/0x20 0x0A` + `0xC3/0xCD` (conditionals), and the `0xFF` `jr $+6` + nops sequence — plus the exact layout arithmetic (`segm_from/to`, `new_address % 0x4000`, `segm_total`, `addr_within_segm >= 0xA000`).
- **Readers** assert the exact decoded tables/bytes at every size boundary (`==`, `±1`), not just "parse succeeded".
- **Type dispatch and strategies** assert the emitted opcode/result on **both sides** of every `==`/`!=`.
- **Optimizer** asserts the exact emitted bytes of each peephole pattern.

Phase ordering matches `tasks.md` Round 3 (11–16): relocation byte-exact (~90 kills) → reader boundary fixtures (~90) → type-dispatch both-sides (~105) → graphics sub-commands (~70) → optimizer + long tail (~65) → fallback + final verification.

- Rationale: the Round 2 result (70%, only ~16 kills) proves branch coverage alone does not kill output-changing mutants; only exact-output assertions do.
- Trade-off: white-box relocation tests couple to the emitted byte layout, but that layout is stable (documented opcode constants) and already referenced by the code comments.

### Decision 11: Exact-output tests classify emitted bytes and never hardcode kernel-derived values

The byte-exact assertions introduced in Round 3 classify each emitted byte by its coupling to the embedded kernel assembly (`bin_header_bin`, generated from `src/infrastructure/kernel/asm/**`), and apply a different assertion strategy per class:

1. **Z80 ISA opcodes** (`0x18`, `0xC3`, `0xCD`, `0xF5`, `0x3E`, `0x21`, …): asserted literally — immutable, defined by the Z80 instruction set.
2. **Compiler-owned MegaROM geometry arithmetic** (`dest[address±N]` index math, `% 0x4000`, `segm_from/to`, `>= 0xA000`): asserted literally — compiler-internal constants that only change with a fundamental mapper redesign.
3. **Kernel-derived addresses** (`mr_call_target`/`mr_jump_target`/`mr_get_data_target` from `bin_header_bin[DISP_MR_* *2]`; `getKernelCallAddr` results; `rom.cpp` mapper-patch `kernelAddr`/`offset`): **derived at test runtime** from `bin_header_bin[]` + `DISP_*`/`def_wrapper_routines_map_table`, mirroring the production expression — never hardcoded, so the test survives a kernel reassembly.
4. **Trampoline/ABI byte sequences** (`F5 08 D9 F1` push/ex af,af'/exx/pop; `jr cc,$+11` = `0x38/0x30/0x28/0x20 0x0A`): a compiler↔kernel contract that must stay in sync with `MR_CALL`/`MR_JUMP` in `61_megarom.asm`. Asserted literally but grouped and commented as "kernel ABI"; a change to the kernel wrapper convention updates compiler.cpp and these tests together.

- Rationale: hardcoding class-3 values would make tests fail on any kernel reassembly (there is an active `chore/kernel-optimize` branch), while the arithmetic mutants those tests target live in the compiler's own index/offset math (classes 1–2), not in the `bin_header_bin` read. Deriving class-3 values preserves the mutant-killing power without the fragility.
- Non-goal: this rule does not relax any class-1/2 assertion; those remain exact.

### Decision 12: Expose `Compiler::getContext()` for white-box relocation tests

The conditional `call nc/nz/c/z` (0xD4/0xC4/0xDC/0xCC) and conditional `jp c/nc` (0xDA/0xD2) relocation switch cases are **never emitted** by the compiler (only `jp z`/`jp nz`/`jp`/`call`/`0xFF` are), yet ~40 of the surviving arithmetic mutants live in those cases. Reaching them requires seeding `context->fixes` directly, but `Compiler::context` was `private` with no accessor. A minimal `shared_ptr<CompilerContext> Compiler::getContext() const` accessor is added (`compiler.h`/`compiler.cpp`), the sole production change in this change, so tests can craft fixes for every reachable opcode case.

- Rationale: without it, the white-box strategy mandated by Decision 4/10 is impossible, and the ~40 conditional-case mutants would remain unreachable.
- Trade-off: relaxes the "no production changes" non-goal by one trivial, behavior-neutral accessor.

### Decision 13: Sentinel fixtures make index/offset mutants distinguishable (the Round 3 lesson)

Round 3 asserted exact bytes but seeded the buffers with **zeros**. An index mutant such as `dest[address - 3]` → `dest[address + 3]` then reads an all-zero cell while the intended cell is also `0x00`, so the assertion still holds and the mutant survives — it is equivalent *for that fixture*, not equivalent in general. Round 4 changes the fixture contract:

- Every seeded buffer used by an index-sensitive test is filled with a **distinct sentinel per offset** (e.g. `buf[i] = 0xA0 + (i & 0x3F)`), and every byte the code under test reads or writes is asserted at its exact position. Any wrong-offset access then produces a value that differs from the sentinel at the asserted position.
- The same rule applies to resource readers (AKM/AKX/SPR/MTF/CSV/blob/data), `compiler_variable_emitter` array-index emission, and `rom.cpp` page patches.
- Rationale: the 73% run shows exact-value assertions alone are insufficient when the fixture's values collide across offsets; sentinel diversity is what converts an index mutant into an observable difference.
- Trade-off: fixtures are slightly larger, but data-driven and cheap.

### Decision 14: `Compiler::write` relocation switch is tested for every opcode, including never-emitted ones

Round 3 treated the `jp m/pe/p/po` and `call p/po/m/pe` switch cases as unreachable and recorded them. Round 4 instead exercises **every** case of the relocation switch white-box, because:

- `Compiler::write` is the unit under test and its input is a caller-provided `dest[]` buffer; `dest[address-1]` may hold any opcode, so the switch is part of the function's contract even for opcodes the current compiler does not emit.
- Seeding these cases is deterministic and asserts the exact documented bytes (`F5 08 D9 F1` + `mr_call_target`/`mr_jump_target` for the `p/po/m/pe` families; the conditional `jr cc,$+11` + `call`/`jp` forms for `nc/nz/c/z`). It kills ~8 additional arithmetic mutants with no new fragility.
- Rationale: "never emitted today" is not "equivalent" — the branch is reachable through the public API and must be covered.
- This supersedes Decision 4's statement that the never-emitted cases are candidates for scope narrowing rather than white-box tests.

### Decision 15: Round 4 phase ordering and kill budget

Round 4 is ordered highest-kill-first, mirroring the Round 3 shape but with sentinel fixtures and the residual branch gaps:

```
Phase 11 — relocation + layout sentinel byte-exact (`compiler.cpp`)          ~35 kills
Phase 12 — reader sentinel fixtures (SPR/AKX/AKM-non-linker/MTF/CSV/blob)    ~55 kills
Phase 13 — compiler semantic byte-exact (expr/optimizer/var/symbol)          ~60 kills
Phase 14 — compiler statement strategies both-sides (set/on/gfx/io/cmd/fn)   ~65 kills
Phase 15 — parser counters & branches (graphics + long tail)                 ~50 kills
Phase 16 — long tail kernel-safe (rom.cpp/symbols/lexer/cli-domain-infra)    ~40 kills
Phase 17 — fallback recording + final verification                            0 kills
```

Budget ≈ 300 kills vs. the 288 required, leaving margin for the ~43 AKM-linker mutants, the dead optimizer branch, and the timeout mutants that are accepted. Phase 17 records, never excludes (Decision 8).

## Risks / Trade-offs

- [Risk: 85% may still be unreachable purely by tests on equality-heavy and relocation arithmetic code] → Mitigation: Round 4 orders the largest residual gaps (relocation sentinel fixtures, readers) first and asserts exact output with sentinel-diverse buffers; the AKM linker state machine, the dead optimizer branch, and timeout mutants are recorded (Phase 17) since `excludePaths` cannot target sub-file regions.
- [Risk: exact-byte fixtures bloat the suite and raise the mull baseline] → Mitigation: keep fixtures minimal and data-driven; the `Slow`-suite exclusion already offsets the single largest test.
- [Risk: white-box relocation tests couple to internal opcode layout] → Mitigation: assert the documented opcode constants (already in the source comments), not internal indices; further, Decision 11 classifies each byte and derives kernel-resolved addresses from `bin_header_bin` instead of hardcoding them, so a kernel reassembly does not break the tests. Round 4 extends this rule to every new test.
- [Risk: sentinel fixtures that accidentally collide with a hardcoded expected byte] → Mitigation: choose sentinels outside the Z80 opcode/expected-value space (e.g. base `0xA0`) and assert positions, not just values; verify with `make -C tests/unit run`.
- [Trade-off: accepting 10 timeout mutants] → They cost < 0.5% of score and are a healthy signal that loops are exercised; not worth eliminating.

## Migration Plan

1. Phases 11–16 (Round 4): add new test cases asserting exact output with sentinel fixtures, verifying each batch with `make -C tests/unit run`. Existing test cases are preserved; new coverage is added through new cases (per the `mutation-testing` spec).
2. After each phase, re-check the surviving list in the latest `mutation_report.json` against the new tests (no full mull run).
3. If equivalent/unreachable mutants remain, record them (Phase 17); `mull.yml` stays unchanged because `excludePaths` is whole-file (Decision 8).
4. Run the full unit suite and confirm all prior tests pass and the count increased.
5. User runs `make mutation-run` + `make mutation-check` once at the end to confirm ≥ 85%.
