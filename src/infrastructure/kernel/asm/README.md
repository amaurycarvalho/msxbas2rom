# Kernel ASM Infrastructure

## Purpose

`src/infrastructure/kernel/asm/` contains the Z80 assembly source and build flow used to generate embedded kernel headers for the C++ application.

## Structure

- `src/`: assembly sources (`header.asm`, `start.asm`, symbols helper, and `header/` domain modules)
- `bin/`: generated binary artifacts (`*.bin`)
- `assets/`: reference assets, external engine data, and helper scripts
- `Makefile`: assembly-to-header build pipeline

## Build Flow

The local makefile compiles ASM and converts binaries into C headers consumed by the kernel layer:

- `src/header.asm` -> `bin/header.bin` -> `../header.h`
- `src/start.asm` -> `bin/start.bin` -> `../start.h`
- `bin/header.bin` + `src/header.symbols.asm` -> `../kernel_manifest_generated.h`
  and `src/infrastructure/kernel/asm/bin/baseline-*`

From repository root:

```bash
make -C src/infrastructure/kernel/asm all
```

## Tooling

Expected tools:

- `pasmo` (Z80 assembler)
- `xxd` (binary to C header converter)
- `pletter` (declared in makefile; compression support)

## Maintenance Policy

- Keep generated artifacts in `bin/` reproducible from sources in `src/`.
- Treat files under `assets/` as supporting inputs/references for kernel-related workflows.
- Prefer updating source ASM and regenerating headers instead of manually editing generated header content.

## Central Table and Dispatcher ABI

The runtime central table contains only dispatch entries used by generated code
and their dependency closure. Two stub forms exist and are generated by
`KernelCentralTable` in `src/domain/kernel/`:

- Resident entry (3 bytes): `C3 lo hi` (`jp target`). No segment switch occurs.
- Paged entry (6 bytes): `CD lo hi ss al ah`. The `CD` bytes call the resident
  dispatcher; `ss` is the 8 KB-pair segment number; `al ah` is the target
  address in the `0x8000-0xBFFF` window.

The paged dispatcher reads the inline segment and address, saves the caller
registers and the previous `SGMADR`, selects the target segment through the
mapper-patched switch, calls the target, restores `SGMADR`, restores the caller
registers, and returns to the original caller. The dispatcher test prototype in
`tests/dispatcher/` verifies register preservation, segment restore, nested
calls, conditional calls, and a timer interrupt during a paged call in openMSX.

Plain ROM has no banked window: its `0x8000-0xBFFF` page is always mapped, so
overflow entries use a direct `jp` stub instead of the dispatcher. MegaROM keeps
the paged dispatcher because its `0x8000` window is banked.

## Deferred Dispatch Fixups

`CompilerCodeOptimizer::addKernelCall()` and `addKernelCallNZ()` emit a 3-byte
call placeholder and record a `DispatchFixup` carrying the `DISP_*` index and
the placeholder operand address. The builder packs the used-module closure,
assigns central-table stub addresses, and patches every fixup to its stub.
Conditional calls use the same fixup mechanism; the inline table metadata is
never executed when the condition is false.
